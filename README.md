# Sistema de Controle de Agenda
## 1. Identificação do Documento

- **Projeto**: Sistema Simples para o coontrole de Agenda Diária Pessoal
- **Versão**: 1.0 
- **Data**: 07/01/2026
- **Análise de Requisitos**: José Anderson Peres de Alencar
- **Gerente do Projeto**: José Anderson Peres de Alencar

## 2. Objetivo do Documento
Este Documento tem como objetivo identificar, analisar, organizar e validar os requisitos do sistema ERP a ser implantado, garantindo que a solução atenda às necessidades do cliente (Projeto utilidado para praticar habilidades de programação).

## 3. Escopo de Análise de Requisitos
A análise de requisitos contempla os seguites módulos:

- Pessoal

Não está incluido neste documento requisitos relacionados a um grupo de pessoas com a agenda coletiva e conexão via servidor (Sem suporte para tal).

## 4. Stakeholders Envolvidos

Stakeholder | Área    | Papel
------------|---------|--------------
Cliente     | Pessoal | Usuário Final

## 5. Metodologia de Levantamento
Os requisitos foram levantados por meio de:

- Entrevistas com o cliente
- Observações de rotinas pessoais

## 6. Requisitos Funcionais
### Modúlo Pessoal

Código | Descrição
-------|-------------------------------------------------
RF-01  | O sistema deve permitir o cadastro de pessoas
RF-02  | O sistema deve permitir a exclusão de pessoas
RF-03  | O sistema deve permitir o cadastro de eventos
RF-04  | O sistema deve permitir a exclusão de eventos
RF-05  | O sistema deve permitir a edição de eventos
RF-06  | O sistema deve emitir aviso de início de eventos
RF-07  | O sistema deve exibir quando o evento de expirou

## 7. Requisitos Não Funcionais

Código | Descrição
-------|-------------------------------------------------------
RNF-01 | O sistema deve estar disponível 99% do tempo
RNF-02 | O tempo de resposta deve ser inferior a 3 segundos
RNF-03 | O sisetam deve ter informçãoes pessoais criptografadas

## 8. Requisitos de Interface
